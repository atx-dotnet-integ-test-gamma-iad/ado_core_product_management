## Security Notes

### Development Environment
- **Username:** postgres (default PostgreSQL superuser)
- **Password:** postgres (placeholder - should be configured per environment)
- **Include Error Detail:** Enabled for debugging

### Production Environment
- **CRITICAL:** Password should NOT be hardcoded in production
- **Recommendation:** Use environment variables or Azure Key Vault/AWS Secrets Manager
- **Best Practice:** Use separate PostgreSQL user with minimal required permissions
- **Include Error Detail:** Disabled for security

### Example Secure Configuration (Production)
```
Host=<pg-server>;Port=5432;Database=ProductManagement;Username=${PG_USERNAME};Password=${PG_PASSWORD};Pooling=true;Timeout=30
```

---

## PostgreSQL-Specific Parameters

### Pooling=true
- Enables connection pooling for better performance
- Reuses existing connections instead of creating new ones
- Recommended for all environments

### Timeout=30
- Connection timeout in seconds
- Prevents hanging connections
- Adjust based on network latency

### Include Error Detail=true
- Provides detailed error messages for debugging
- **Development Only:** Exposes implementation details
- Remove or set to false in production

### Port=5432
- PostgreSQL default port
- Explicitly specified for clarity
- Adjust if PostgreSQL runs on different port

---

## Removed SQL Server Parameters

### Trusted_Connection=True
- Windows Integrated Authentication
- Not supported by PostgreSQL
- Replaced with explicit username/password

### MultipleActiveResultSets=true
- SQL Server feature for multiple result sets on same connection
- Not needed in PostgreSQL
- PostgreSQL handles this differently

### TrustServerCertificate=True
- SQL Server SSL certificate validation
- Not applicable to PostgreSQL
- PostgreSQL uses different SSL configuration
