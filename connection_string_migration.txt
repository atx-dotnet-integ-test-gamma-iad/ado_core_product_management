================================================================================
DETAILED PARAMETER EXPLANATIONS
================================================================================

1. Server → Host
   -----------
   SQL Server: Server=localhost
   PostgreSQL: Host=localhost
   
   PostgreSQL uses "Host" instead of "Server" to specify the database server location.

2. Port Addition
   -------------
   SQL Server: [Implicit, typically 1433]
   PostgreSQL: Port=5432
   
   PostgreSQL default port is 5432. Explicitly specified for clarity.

3. Database Name
   -------------
   SQL Server: Database=ProductManagement
   PostgreSQL: Database=ProductManagement
   
   No changes required. Database name remains the same.

4. Authentication
   --------------
   SQL Server: Trusted_Connection=True (Windows Authentication)
   PostgreSQL: Username=postgres;Password=postgres (PostgreSQL Authentication)
   
   PostgreSQL does not support Windows Integrated Authentication in the same way.
   Changed to username/password authentication.
   
   NOTE: In production environments, credentials should be:
   - Stored in secure configuration (Azure Key Vault, AWS Secrets Manager, etc.)
   - Not hardcoded in appsettings.json
   - Different for each environment

5. MultipleActiveResultSets
   -------------------------
   SQL Server: MultipleActiveResultSets=true
   PostgreSQL: [Removed]
   
   This is a SQL Server specific optimization that allows multiple result sets
   on a single connection. PostgreSQL handles this differently and does not
   require this parameter.

6. TrustServerCertificate
   -----------------------
   SQL Server: TrustServerCertificate=True
   PostgreSQL: [Removed]
   
   This is a SQL Server specific parameter for SSL/TLS connections.
   PostgreSQL has its own SSL configuration parameters if needed:
   - SSL Mode=Require (to enforce SSL)
   - SSL Mode=Prefer (to prefer SSL if available)

7. Connection Pooling
   ------------------
   SQL Server: [Implicit, enabled by default]
   PostgreSQL: Pooling=true
   
   Added explicitly to enable connection pooling. Npgsql supports additional
   pooling parameters:
   - Minimum Pool Size=1 (default: 1)
   - Maximum Pool Size=20 (default: 100)

================================================================================
PRODUCTION RECOMMENDATIONS
================================================================================

1. Credentials Management
   ----------------------
   DO NOT store passwords in appsettings.json for production.
   
   Options:
   - Environment variables
   - Azure Key Vault (for Azure deployments)
   - AWS Secrets Manager (for AWS deployments)
   - Docker secrets (for containerized deployments)
   - Configuration providers with encryption

2. Connection String Template for Production
   -----------------------------------------
   Host={DB_HOST};Port={DB_PORT};Database={DB_NAME};Username={DB_USER};Password={DB_PASSWORD};Pooling=true;Maximum Pool Size=50;SSL Mode=Require

3. Security Best Practices
   ------------------------
   - Use strong passwords for database users
   - Limit database user permissions (principle of least privilege)
   - Enable SSL/TLS for connections
   - Use separate database users for different environments
   - Rotate credentials regularly
   - Monitor connection usage and performance

4. Performance Tuning
   -------------------
   - Adjust pool sizes based on application load
   - Monitor connection pool exhaustion
   - Use appropriate timeout values
   - Consider read replicas for read-heavy workloads
