REFACTORING APPROACH
============================================================================

Instead of using SQL Server procedural syntax (BEGIN TRANSACTION, DECLARE, SET),
the code now uses:
- C# NpgsqlTransaction objects for transaction management
- Separate SQL commands executed within the transaction context
- RETURNING clause for getting inserted IDs (PostgreSQL native feature)
- C# variables instead of SQL variables
- Explicit transaction commit/rollback in C# code

----------------------------

KEY CHANGES:
- Removed: DECLARE @NewProductId, BEGIN TRANSACTION, COMMIT, SET

- Converted: Single SQL batch → 3 separate commands with shared transaction

POSTGRESQL COMPATIBILITY IMPROVEMENTS
============================================================================

1. SCOPE_IDENTITY() Replacement:
   - SQL Server: SCOPE_IDENTITY() function
   - PostgreSQL: RETURNING clause on INSERT statement
   - Better: Native PostgreSQL feature, more reliable

2. Transaction Management:
   - SQL Server: BEGIN TRANSACTION...COMMIT in SQL
   - PostgreSQL: BeginTransactionAsync() in C# code
   - Better: Consistent with ADO.NET best practices

3. Variable Scope:
   - SQL Server: SQL variables with DECLARE/SET
   - PostgreSQL: C# variables
   - Better: Type-safe, compile-time validation

4. Error Handling:
   - SQL Server: Implicit rollback on error
   - PostgreSQL: Explicit try/catch with rollback
   - Better: Clear error handling semantics

5. Product Existence Validation:
   - SQL Server: Implicit (would fail on constraint)
   - PostgreSQL: Explicit validation with descriptive error
   - Better: User-friendly error messages
