## Behavior Differences & Notes

### Connection Handling
- `NpgsqlConnection` behavior is identical to `SqlConnection` for our use case
- ConnectionState enum works the same
- OpenAsync(), CloseAsync(), DisposeAsync() methods compatible

### Command Execution
- `NpgsqlCommand` fully compatible with existing patterns
- ExecuteScalarAsync(), ExecuteNonQueryAsync(), ExecuteReaderAsync() work identically
- Named parameters (@ParamName) supported by Npgsql driver

### Parameter Handling
- AddWithValue() method works the same with Npgsql
- No explicit NpgsqlParameter objects needed for our simple parameter usage
- Type inference works correctly for our data types (int, string, decimal, DateTime)

### Transaction Handling
- connection.BeginTransactionAsync() returns NpgsqlTransaction (compatible)
- CommitAsync() and RollbackAsync() work identically
- ExecuteInTransactionAsync method requires no changes

### Data Reader
- NpgsqlDataReader interface identical to SqlDataReader
- Column access by name works the same
- Type conversion methods (Convert.ToInt32, etc.) work identically
- DBNull.Value handling unchanged
