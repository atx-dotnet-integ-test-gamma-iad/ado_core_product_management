KEY POSTGRESQL SYNTAX CONVERSIONS
==================================================================================

1. SCOPE_IDENTITY() → RETURNING clause
   - SQL Server: SET @NewProductId = SCOPE_IDENTITY();
   - PostgreSQL: INSERT INTO Products (...) VALUES (...) RETURNING ProductId;
   - Impact: 1 statement (InsertProductAsync)

2. GETDATE() → CURRENT_TIMESTAMP
   - All instances replaced consistently
   - Impact: 7 occurrences across 3 statements (Insert, Update, Delete)

3. DECLARE variables → CTE WITH clause
   - SQL Server: DECLARE @OldPrice DECIMAL(18,2); SELECT @OldPrice = Price...
   - PostgreSQL: WITH old_values AS (SELECT Price as OldPrice...)
   - Impact: 2 statements (UpdateProductAsync, DeleteProductAsync)

4. BEGIN TRANSACTION/COMMIT → Implicit/CTE-based
   - SQL Server: BEGIN TRANSACTION; ...operations...; COMMIT;
   - PostgreSQL: CTE-based approach with atomic operations
   - Impact: 3 statements (Insert, Update, Delete)

5. Window Functions (AVG, COUNT, LAG, RANK, PERCENT_RANK) OVER()
   - No changes required - fully PostgreSQL compatible
   - Impact: 5 statements use window functions
