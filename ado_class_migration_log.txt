Functional Equivalence:
-----------------------
NpgsqlCommand provides identical functionality to SqlCommand:
- Implements IDbCommand interface
- CommandText property for SQL
- Parameters collection (Parameters.AddWithValue)
- ExecuteReaderAsync() for SELECT queries
- ExecuteScalarAsync() for single value returns
- ExecuteNonQueryAsync() for INSERT/UPDATE/DELETE
- Transaction support (optional transaction parameter)
- Prepared statement support

Key Differences:
----------------
- Parameter naming: @ParamName syntax works (Npgsql handles automatically)
- PostgreSQL supports positional parameters ($1, $2) but @names also work
- Some PostgreSQL-specific command types available
- Different timeout behavior (PostgreSQL server-side vs client-side)

Compatibility Notes:
--------------------
- Parameters.AddWithValue("@Name", value) works identically
- No code changes needed for parameter handling
- ExecuteReaderAsync(), ExecuteScalarAsync(), ExecuteNonQueryAsync() all compatible
- Using statement with IDisposable works the same
- Async/await patterns identical

Functional Equivalence:
-----------------------
NpgsqlDataReader provides identical functionality to SqlDataReader:
- Implements IDataReader interface
- Field access by name: reader["ColumnName"]
- Field access by ordinal: reader[0], reader[1], etc.
- Type conversion methods: GetInt32(), GetString(), GetDecimal(), GetDateTime()
- ReadAsync() for asynchronous iteration
- IsDBNull() for null checking
- Close() and Dispose() support

Key Differences:
----------------
- PostgreSQL type system differences (handled automatically)
- Some PostgreSQL-specific data types available
- Different behavior for certain edge cases (e.g., date ranges)

Compatibility Notes:
--------------------
- reader["ColumnName"] works identically
- Convert.ToXxx(reader["Column"]) pattern works the same
- DBNull.Value checks work identically
- Using statement works the same
- No code changes required for this method
