METHOD 3: InsertProductAsync
================================================================================
Line Numbers: 126-172
SQL Statement: MAJOR REFACTORING REQUIRED
Rationale: PostgreSQL does not support SCOPE_IDENTITY() or GETDATE()

Original SQL Structure:
- Single multi-statement batch with BEGIN TRANSACTION/COMMIT
- Used SCOPE_IDENTITY() to capture new ID
- Used GETDATE() for timestamps
- All statements executed as single batch

PostgreSQL Changes Applied:
1. Replaced SCOPE_IDENTITY() with RETURNING clause:
   FROM: SET @NewProductId = SCOPE_IDENTITY();
   TO:   INSERT INTO ... RETURNING ProductId

2. Replaced GETDATE() with CURRENT_TIMESTAMP:
   FROM: ActionDate = GETDATE()
   TO:   ActionDate = CURRENT_TIMESTAMP

3. Split transaction into separate statements:
   - INSERT with RETURNING (ExecuteScalarAsync)
   - INSERT for ProductHistory (ExecuteNonQueryAsync)
   - UPDATE for ProductStats (ExecuteNonQueryAsync)

4. Transaction handling moved to ADO.NET layer (ExecuteInTransactionAsync can be used if needed)

Code Structure Changes:
- Introduced three separate SQL string constants: insertSql, historySql, statsSql
- Changed from single command to three separate command objects
- Captured newProductId from first command
- Used C# variable to pass ProductId to subsequent statements

Comments Added: "// PostgreSQL: Use RETURNING instead of SCOPE_IDENTITY(), CURRENT_TIMESTAMP instead of GETDATE()"
